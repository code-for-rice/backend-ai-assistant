### 3. Design the Business Database (`db/schema.sql`)

Create 3 relational tables with foreign keys (`customers`, `orders`, and `support_tickets`) so the MCP Server can perform realistic lookups (such as retrieving an order by code or filtering open tickets by customer email):

```sql
CREATE TABLE IF NOT EXISTS customers (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    full_name TEXT NOT NULL,
    email TEXT UNIQUE NOT NULL,
    tier TEXT CHECK(tier IN ('standard', 'vip')) DEFAULT 'standard',
    created_at TEXT DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE IF NOT EXISTS orders (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    order_code TEXT UNIQUE NOT NULL,
    customer_id INTEGER NOT NULL,
    product_name TEXT NOT NULL,
    total_amount REAL NOT NULL,
    status TEXT CHECK(status IN ('pending', 'shipping', 'delivered', 'cancelled')) NOT NULL,
    updated_at TEXT DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (customer_id) REFERENCES customers(id)
);

CREATE TABLE IF NOT EXISTS support_tickets (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    customer_id INTEGER NOT NULL,
    order_id INTEGER,
    subject TEXT NOT NULL,
    priority TEXT CHECK(priority IN ('low', 'medium', 'high')) DEFAULT 'medium',
    status TEXT CHECK(status IN ('open', 'in_progress', 'resolved')) DEFAULT 'open',
    created_at TEXT DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (customer_id) REFERENCES customers(id),
    FOREIGN KEY (order_id) REFERENCES orders(id)
);
```

## B. Build an MCP Server with FastMCP: 1 Resource and 2 Tools Reading Directly from SQLite (Day 2: Oct 22, 2026)

### 1. Review the Difference Between Tools and Resources

Before diving into the implementation, you only need to understand two foundational MCP concepts:

- **Tool (`@mcp.tool`) — Model-controlled:** Parameterized functions that the LLM can choose to invoke when it needs to retrieve data or perform an action. FastMCP automatically converts Python type hints into a JSON Schema and uses docstrings to help the LLM understand when and how to call each tool *(FastMCP Docs)*.
- **Resource (`@mcp.resource`) — Application-controlled:** Read-only data sources identified by a URI (e.g., `db://schema`), allowing clients to provide the LLM with pre-loaded static content or structured system information.

### 2. Set Up the Virtual Environment and Install FastMCP

From the project root (`backend-ai-assistant`), create a virtual environment, activate it, and install `fastmcp`:

### 3. Implement the MCP Server (`mcp_server/server.py`)

Two key best practices for backend developers: always use parameterized queries (`?`) to prevent SQL injection, and resolve file paths relative to `__file__` so the server can always locate `data/app.db` regardless of the working directory it is launched from:

```python
import sqlite3
from pathlib import Path
from typing import Any
from fastmcp import FastMCP

# Resolve the path to data/app.db relative to the project root
DB_PATH = Path(__file__).resolve().parent.parent / "data" / "app.db"

mcp = FastMCP("BackendSupportMCP")


def get_connection() -> sqlite3.Connection:
    conn = sqlite3.connect(DB_PATH)
    conn.row_factory = sqlite3.Row  # Return dict-like rows instead of tuples
    return conn


@mcp.resource("db://schema")
def get_database_schema() -> str:
    """Return the schema of all existing tables in the database."""
    with get_connection() as conn:
        rows = conn.execute(
            "SELECT name, sql FROM sqlite_master WHERE type='table' AND name NOT LIKE 'sqlite_%'"
        ).fetchall()
    return "\n\n".join(f"-- Table: {row['name']}\n{row['sql']}" for row in rows)


@mcp.tool()
def get_order_by_code(order_code: str) -> dict[str, Any]:
    """Look up order details by order_code (e.g., ORD-1001), including customer information."""
    with get_connection() as conn:
        row = conn.execute(
            """
            SELECT o.order_code, o.product_name, o.total_amount, o.status, o.updated_at,
                   c.full_name AS customer_name, c.email AS customer_email, c.tier AS customer_tier
            FROM orders o
            JOIN customers c ON o.customer_id = c.id
            WHERE o.order_code = ?
            """,
            (order_code.strip().upper(),),
        ).fetchone()

    if not row:
        return {"found": False, "message": f"Order '{order_code}' was not found."}

    return {"found": True, "order": dict(row)}


@mcp.tool()
def list_support_tickets(
    status: str | None = None,
    priority: str | None = None,
) -> list[dict[str, Any]]:
    """
    Filter support tickets from the database.
    - status: 'open', 'in_progress', or 'resolved' (leave empty to fetch all)
    - priority: 'low', 'medium', or 'high' (leave empty to fetch all)
    """
    query = """
        SELECT t.id, t.subject, t.priority, t.status, t.created_at,
               c.full_name AS customer_name, c.tier AS customer_tier,
               o.order_code
        FROM support_tickets t
        JOIN customers c ON t.customer_id = c.id
        LEFT JOIN orders o ON t.order_id = o.id
        WHERE 1=1
    """
    params: list[Any] = []

    if status:
        query += " AND t.status = ?"
        params.append(status.strip().lower())
    if priority:
        query += " AND t.priority = ?"
        params.append(priority.strip().lower())

    query += " ORDER BY t.created_at DESC"

    with get_connection() as conn:
        rows = conn.execute(query, params).fetchall()

    return [dict(row) for row in rows]


if __name__ == "__main__":
    mcp.run()
```

### 4. Test the MCP Server and Commit to GitHub (~10 minutes)

You have two quick ways to test the server locally:

1. **Test with the visual UI (MCP Inspector):** Run the following command (requires Node.js) to open the inspector in your browser. Inspect the **Tools** and **Resources** tabs, then try calling `get_order_by_code` with `"ORD-1001"` and `list_support_tickets` with `status="open"`:

   ```bash
   fastmcp dev inspector mcp_server/server.py
   ```

2. **Test with an in-process Python Client (no Node.js required):** Create `mcp_server/test_client.py` and run `python mcp_server/test_client.py`:

   ```python
   import asyncio
   from fastmcp import Client
   from server import mcp


   async def main():
       async with Client(mcp) as client:
           tools = await client.list_tools()
           print("Tools:", [t.name for t in tools])

           order = await client.call_tool("get_order_by_code", {"order_code": "ORD-1001"})
           print("Order result:", order)

           tickets = await client.call_tool("list_support_tickets", {"status": "open"})
           print("Open tickets:", tickets)


   asyncio.run(main())
   ```

Once both tools and the resource return valid data from `data/app.db`, commit and push your changes to GitHub:

```bash
git add mcp_server/ requirements.txt
git commit -m "feat(mcp): add initial MCP server with order lookup and ticket filter tools"
git push origin main
```

> **Note on running an MCP Server over `stdio`:** Never use `print()` for debugging inside `server.py`, because `stdout` is reserved for MCP JSON-RPC protocol messages. If you need debug logs, use Python's `logging` module configured to write to `sys.stderr` (we will complete this in the Day 3 task).
